## 원 요청과의 대응

| 요청 항목 | 대응 문서 | 비고 |
|-----------|----------|------|
| 1. GitHub Action 모니터링 | 제품 전체 | 범위: 조직 전체 레포 |
| 2. 로그 수집 (webhook + 누락 backfill) | PRD-1 | "로그"를 **실행 이벤트**로 해석. 실행 **로그 본문** 수집은 범위 제외로 명시 |
| 3. S3 datalake + TTL (Hive 일 단위 파티션) | PRD-2 | 파티션 기준을 **수신 시각**으로 확정, 근거 명시 |
| 4. Bronze→Silver, repo/workflow/job/step 구분 | PRD-3 | **run 계층 추가** (4→5계층) |

### 해석·보강한 부분 (확인 필요)

1. **"로그 수집"의 범위** — 워크플로 실행 로그 본문(텍스트)이 아니라 실행 이벤트 메타데이터로 해석했다. 로그 본문이 필요하면 용량 특성이 완전히 달라 별도 PRD가 필요하다
2. **run 계층 추가** — 재실행(`run_attempt`) 구분을 위해 필수라고 판단했다
3. **Bronze 파티션 = 수신 시각 기준** — append-only 보장을 위한 선택. 대신 Bronze 직접 조회 시 비즈니스 일자와 어긋나며, Silver에서 해소된다
4. **TTL 90일 / 730일** — 제안값. Bronze TTL이 곧 Silver 재구축 가능 범위의 상한이다
